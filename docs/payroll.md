# เงินเดือนและค่าจ้าง

เมนู **เงินเดือน** ใช้รายชื่อพนักงานเดิมจาก **รายชื่อ / ผู้ติดต่อ → พนักงาน** ในพื้นที่ทำงานของผู้ใช้แต่ละคนตามแบบสิทธิ์เดิมของ BillFlow ไม่ได้รวมบัญชีของพนักงานเข้ากับบัญชีเจ้าของร้าน

1. สร้างร่าง เลือกพนักงาน รอบวันที่ วันครบกำหนด ค่าจ้างรายเดือน / รายวัน / รายชั่วโมง และจำนวนหน่วย
2. เพิ่มรายได้ เช่น OT เบี้ยเลี้ยง โบนัส คอมมิชชัน และรายการหักแยกประเภท ภาษี ประกันสังคม กองทุน เงินเบิกล่วงหน้า ขาดงาน และอื่น ๆ
3. ตรวจยอดแล้วอนุมัติ กำหนดวันลงบัญชี ยอดที่อนุมัติแล้วล็อกไว้ การแก้ไขให้คืนรายการจ่ายทั้งหมดและยกเลิกรอบพร้อมเหตุผล แล้วจัดทำใหม่
4. จ่ายได้หลายครั้ง แต่ละครั้งระบุยอด วันที่ บัญชี วิธีจ่าย อ้างอิง หมายเหตุ และแนบหลักฐาน ยอดจ่ายห้ามเกินยอดสุทธิคงเหลือ
5. ดูประวัติแบ่งจ่าย พิมพ์สลิป / บันทึก PDF ผ่านหน้าต่างพิมพ์ และส่งออกสรุป CSV ตามเดือนสิ้นสุดรอบ

จำนวนเงินเก็บเป็นสตางค์ ค่าจ้างรายวันและรายชั่วโมงคำนวณจากหน่วย × อัตราแล้วปัดครั้งเดียว รายการ OT รับเป็นยอดรวมที่ตรวจสอบแล้ว ภาษีเป็นยอดกรอกเอง ประกันสังคมมีตัวช่วยคำนวณ ม.33 หรือกรอกยอดที่ตรวจสอบแล้วเอง ไม่มีการยื่น ภ.ง.ด.1 / สปส.1-10 หรือคำนวณภาษีรายปีอัตโนมัติ เงินเบิกล่วงหน้าที่หักต้องมีลูกหนี้พนักงานบันทึกไว้ก่อน

## บัญชี

อนุมัติแล้วตั้งรายได้รวมเข้าค่าใช้จ่าย 520000 หักขาดงานเครดิตลดค่าใช้จ่าย ภาษีค้างจ่าย 213000 ประกันสังคม 216000 กองทุน 217000 รายการหักอื่นรอนำส่ง 218000 และเงินเดือนสุทธิค้างจ่าย 219000 เงินเบิกล่วงหน้าตัดลูกหนี้อื่น 111000 เงินสมทบนายจ้างตั้งค่าใช้จ่าย 522000 และหนี้ประกันสังคม 216000

จ่ายเงินจริงสร้างรายการเงินออกหนึ่งครั้งและเดบิต 219000 โดยไม่ตั้งค่าใช้จ่ายเงินเดือนซ้ำ ยกเลิกการจ่ายต้องยืนยันว่าได้รับเงินคืนจริง ระบบเพิ่มเงินรับกลับเข้าบัญชีเดิมและเก็บรายการเดิมทั้งหมด ยกเลิกเงินเดือนกลับรายการตั้งค้างจ่าย ณ วันที่ยกเลิก รายการอนุมัติและกลับรายการคำนวณใน postings จากหลักฐานเงินเดือน ส่วนกระแสเงินสดอ่านรายการจ่าย / รับเงินจริง

## สิทธิ์และประวัติ

เจ้าของเข้าถึงได้เสมอ สามารถกำหนดให้ดู / แก้ไขเมนูเงินเดือนแยกกัน ผู้จัดการที่เลือกใช้สิทธิ์มาตรฐานจะได้เมนูนี้ พนักงานทั่วไปและแอดมินร้านไม่ได้สิทธิ์นี้โดยอัตโนมัติ ผู้มีสิทธิ์เงินเดือนต้องมีสิทธิ์แก้ไขรายการรับ–จ่ายร่วมด้วยจึงจ่าย / คืนเงินได้ สิทธิ์การอ่านข้อมูลการเงินยังใช้การฉายข้อมูลทางการเงินชุดเดียวกับเมนูสมุดบัญชีและรายงานเดิม

ฐานข้อมูลตรวจยอดและความเชื่อมโยงการจ่าย ล็อกยอดอนุมัติ รายการจ่ายเดิม และป้องกันเบราว์เซอร์รุ่นเก่าลบข้อมูลเงินเดือนโดยไม่ตั้งใจ ทุกการเปลี่ยนเงินเดือนบันทึกประวัติฝั่งเซิร์ฟเวอร์พร้อมข้อมูลผู้ใช้งานและอุปกรณ์เดิม การล้างข้อมูลทั้งระบบยังอยู่ภายใต้ตัวป้องกันสมุดบัญชีเดิม

## ตรวจสอบ

`npm test` รวมกรณีอนุมัติ เงินเดือนค้างจ่าย แบ่งจ่ายสองครั้ง จ่ายเกิน คืนรายการ กลับบัญชี รายวัน รายชั่วโมง และการล็อกประวัติ

`tests/payroll.sql` ตรวจฐานข้อมูลผ่านบทบาท authenticated พร้อมย้อนกลับธุรกรรมท้ายชุด จึงไม่คงข้อมูลทดสอบ


## แบบฟอร์มและเอกสารจาก LINE

สลิปมีเลขเอกสาร สำเนาร้าน / พนักงาน รหัสพนักงาน แผนก ช่วงวันที่ วันหยุด วันทำการ วันลา ขาดงาน วันทำงานจริง อัตราจ้าง และเงินเดือนเต็มเดือนอ้างอิง รายได้และรายการหักอยู่สองฝั่งตามตัวอย่าง พร้อมจำนวน × อัตรา ยอดรวม สุทธิเป็นตัวเลขและตัวอักษร วันที่แจ้ง / จ่ายจริง วิธีจ่าย หลักประกันอ้างอิง และผู้ลงนาม สามารถกำหนดข้อความท้ายเอกสารได้ ข้อมูลวันทำงานและหลักประกันอ้างอิงไม่หักเงินซ้ำอัตโนมัติ

รูปเงินเดือนจากกลุ่ม LINE เดิมจะถูกแยกเป็นเอกสารชนิด payroll ระบบอ่านค่าจ้าง รายได้ หัก และข้อมูลวันทำงานลงแบบตรวจเอกสารเงินเดือน จับคู่พนักงานด้วยรหัส / ชื่อที่ตรงเพียงคนเดียวเท่านั้น หากรหัสและชื่อขัดกันต้องเลือกเอง ไม่สร้างพนักงานใหม่อัตโนมัติ การแปลงหน่วยบาทเป็นสตางค์เกิดเพียงครั้งเดียว รายการหักจำนวน 3 × อัตรา 19 บาท = 57 บาทจะเก็บจำนวน อัตรา และยอดแยกกัน

ก่อนยืนยันต้องเทียบรายได้รวม หักรวม และสุทธิกับยอดจากรูป หากไม่ตรงต้องตรวจแก้ ระบบยืนยันเข้าร่างเงินเดือนพร้อมแนบรูปเดิมเท่านั้น ไม่สร้างรายการจ่ายหรือประวัติชำระจากการอ่านภาพแม้ภาพติ๊กว่าโอนเงินแล้ว ต้องอนุมัติและบันทึกแบ่งจ่ายตามหลักฐานแยกต่างหาก รองรับข้อมูลเก่าไม่มีรายละเอียดแบบฟอร์ม เอกสารที่อนุมัติแล้วยังคงล็อกข้อมูลเดิม

ทดสอบตัวอย่างค่าแรง 300 × 12 = 3,600 บาท หักประกันสังคม 350 และรายการ 3 × 19 = 57 รวมรายการหัก 407 สุทธิ 3,193 บาท โดยไม่ใช้ข้อมูลพนักงานจริง ชุด SQL ตรวจยืนยันนำเข้าจาก LINE ป้องกันสูตรผิด วันเกินรอบ และนำเข้าซ้ำ แล้ว rollback ข้อมูลทดสอบทั้งหมด


### สถานะการเปิดใช้ตัวอ่านเงินเดือน

ผู้ใช้อนุญาตชัดเจนให้ส่งภาพเงินเดือนจากกลุ่ม LINE ที่ผูกไว้ไปยัง Google Gemini เพื่ออ่านและกรอกแบบฟอร์ม เมื่อวันที่ 29 ตุลาคม 2569 เผยแพร่ billflow-line เวอร์ชัน 13 สำเร็จและตรวจสอบว่า source ตัวอ่านตรงกับที่ทดสอบ พร้อมคงการยืนยันตัวตนและ CORS เดิม ไม่ส่งข้อความหรือรูปทดสอบเข้ากลุ่ม LINE ในการเปิดใช้ครั้งนี้ ยังไม่ได้ทดสอบส่งภาพจริงผ่าน LINE หลัง deploy การอ่านต้องใช้ Gemini API key และโควตาที่ตั้งค่าไว้ ผลเข้าร่างรอตรวจ ไม่สร้างรายการจ่ายจากภาพอัตโนมัติ


## รับ PDF จาก LINE

ส่งไฟล์ PDF ผ่านกลุ่มเดิม รองรับไม่เกิน 5 MB โดยตรวจนามสกุลและส่วนหัวไฟล์ PDF ก่อนเก็บต้นฉบับและส่งให้ Gemini ด้วย MIME application/pdf ใช้การตรวจลายเซ็น LINE การจำกัดกลุ่ม และโควตาเดิม ป้องกันรูปหรือ PDF ซ้ำด้วยแฮชเนื้อหาเดิม หน้าเปิดตรวจแสดง PDF และมีลิงก์เปิดต้นฉบับในแท็บใหม่

PDF หลายหน้าที่เป็นเอกสารเดียวกันอ่านร่วมกันได้ แต่หากตัวอ่านตรวจพบหลายพนักงาน / หลายเอกสารในไฟล์เดียวจะไม่ยอมรวมยอด ต้องแยกไฟล์ก่อนนำเข้า ผลเงินเดือนยังเป็นร่าง ไม่ตัดบัญชีอัตโนมัติ ชื่อไฟล์แนบในระบบคงนามสกุล .pdf และ MIME เดิม ไฟล์ติดรหัสผ่านหรือเสียหายต้องแก้ที่ต้นฉบับ

ทดสอบรับ webhook PDF การตรวจส่วนหัว/ขนาด การส่งไบต์ PDF ให้ตัวอ่านจำลอง การแปลงยอดเงินเข้าร่าง และการไม่รวมหลายพนักงาน ยังไม่ได้ส่ง PDF จริงผ่านกลุ่ม LINE ในการอัปเดตครั้งนี้

## ใบรับเงินเดือน PDF และส่งออก LINE

ในรายละเอียดเงินเดือนมีปุ่ม **ใบรับเงิน / ดาวน์โหลด PDF** เลือกใบแจ้งเงินเดือนหรือใบรับเงินเฉพาะงวดที่จ่ายจริง เลือกสำเนาร้าน / พนักงานได้ ใบรับเงินอ้างอิงเลขงวด R001 เป็นต้นไป และแสดงยอดจ่ายครั้งนี้แยกจากสุทธิทั้งรอบ ยอดจ่ายสะสม และคงเหลือ มีช่องลงชื่อผู้จัดการและผู้รับเงิน เอกสารร่างหรือยกเลิกมีข้อความกำกับ ไม่ออกใบรับเงินจากรายการที่ยังไม่จ่ายหรือคืนรายการแล้ว ฝังฟอนต์ Sarabun ตาม SIL OFL ใน PDF และสร้างไฟล์ในอุปกรณ์ผู้ใช้

เจ้าของสามารถกด **ส่ง PDF ทาง LINE** ระบบแสดงกลุ่มปลายทาง ประเภทเอกสาร พนักงาน และงวดจ่ายก่อนให้ติ๊กยืนยัน สมาชิกกลุ่มที่ได้รับลิงก์สามารถเปิดและดาวน์โหลดได้ภายใน 24 ชั่วโมง ส่งเป็นข้อความพร้อมลิงก์ PDF ในพื้นที่เก็บไฟล์ส่วนตัว เนื่องจาก LINE Messaging API ไม่มีข้อความส่งไฟล์ PDF โดยตรง ผู้ใช้ดาวน์โหลด PDF แล้วแนบส่งเองใน LINE ได้ด้วย

เซิร์ฟเวอร์ตรวจเจ้าของ เลข revision ของบัญชี เงินเดือนอนุมัติแล้ว รายการจ่ายจริง กลุ่มที่ยืนยัน และ PDF ในโฟลเดอร์ของเจ้าของเท่านั้น ใช้ X-Line-Retry-Key กับรหัสคำขอเดิมป้องกันส่งซ้ำ บันทึกประวัติการส่งโดยไม่เปิดตารางให้ผู้ใช้ทั่วไปหรือบุคคลภายนอกอ่าน การพัฒนาครั้งนี้ทดสอบการส่งด้วยบริการจำลอง ไม่ได้ส่งเอกสารเงินเดือนจริงเข้ากลุ่ม


## ตัวช่วยคำนวณประกันสังคม ม.33

ในแบบร่างเงินเดือน ก่อนรายการหัก กรอกค่าจ้างที่ใช้ส่งประกันสังคมรวมทั้งเดือน ตั้งฐานขั้นต่ำ/สูงสุดและอัตราพนักงาน/นายจ้าง แล้วกด **นำยอดคำนวณไปใช้ในรอบนี้** ตัวช่วยแทนที่รายการหักประกันสังคมเดิมโดยไม่เพิ่มซ้ำ และตั้งเงินสมทบนายจ้างแยกจากสุทธิพนักงาน ยอดใช้ในสลิป รายงาน และบัญชีผ่านข้อมูลเงินเดือนเดิม การเปลี่ยนค่าตัวช่วยยังไม่เปลี่ยนยอดจนกดนำไปใช้ และต้องบันทึกแบบร่างตามปกติ

ค่าเริ่มต้นอัตรา 5% ต่อฝ่าย ฐานขั้นต่ำ 1,650 บาท ฐานสูงสุดตามปีสิ้นสุดรอบ: ก่อนปี 2569 เท่ากับ 15,000 บาท; ปี 2569–2571 เท่ากับ 17,500 บาท; ปี 2572–2574 เท่ากับ 20,000 บาท; ปี 2575 เป็นต้นไปเท่ากับ 23,000 บาท ปัดเงินสมทบเป็นบาท เศษตั้งแต่ 50 สตางค์ขึ้นไปปัดขึ้น ค่าจ้างศูนย์คำนวณศูนย์ ต้องตรวจสถานะผู้ประกันตนและข้อยกเว้นก่อนใช้ อัตรา/ฐานปรับได้ในแบบฟอร์มเพื่อรองรับประกาศเฉพาะช่วงหรือพื้นที่ ค่าปรับใช้เฉพาะระหว่างเปิดแบบฟอร์ม ไม่ใช่นโยบายร้านถาวร

ตัวช่วยหักเงินสมทบจากรอบอื่นของพนักงานคนเดียวกันที่อนุมัติแล้วในเดือนสิ้นสุดรอบเดียวกัน ยอดคงเหลือต่ำสุดศูนย์ ไม่แก้ประวัติที่อนุมัติแล้ว ต้องตรวจร่างอื่นก่อนอนุมัติ หากอนุมัติหลายร่างพร้อมกันจากหลายอุปกรณ์ต้องตรวจยอดรวมรายเดือนอีกครั้ง รอบข้ามเดือนไม่เปิดใช้ตัวช่วย ให้แยกรอบตามเดือนหรือกรอกยอดเอง ใช้เฉพาะ ม.33 ไม่ใช่ ม.39/40 และไม่ยื่นหรือนำส่งเงินให้สำนักงานประกันสังคม

## ไฟล์แนบ Excel สำหรับนำส่ง สปส. แบบกำหนดเอง

ที่หน้าเงินเดือน กด **จัดทำไฟล์นำส่ง สปส.** เหนือสรุปยอดประกันสังคม ระบุบัญชีนายจ้าง สาขา ชื่อสถานประกอบการ งวดเดือน วันที่ และอัตราทั้งสองฝ่าย เพิ่มแถวกรอกเอง เลือกชื่อพนักงาน หรือดึงเงินเดือนที่อนุมัติในเดือนที่เลือกได้ การดึงรวมทุกรอบของพนักงานคนเดียวกัน โดยไม่รวมร่างและรายการยกเลิก ค่าจ้างที่ดึงเป็นรายได้รวม จึงต้องตรวจองค์ประกอบค่าจ้างที่ใช้ส่งประกันสังคม และกรอกเลขประจำตัวประชาชน/เลขที่บัตรประกันสังคมของต่างด้าวให้ถูกต้อง ชื่อที่แยกให้อัตโนมัติเป็นค่าตั้งต้นให้ตรวจแก้ได้

ดาวน์โหลด `.xlsx` มีคอลัมน์ A–F ตรงกับ SampleExcel ที่ผู้ใช้แนบ: เลขประจำตัวประชาชน, คำนำหน้าชื่อ, ชื่อผู้ประกันตน, นามสกุลผู้ประกันตน, ค่าจ้าง, จำนวนเงินสมทบ โดยชื่อชีตเป็นรหัสสาขา 6 หลัก เก็บเลขประจำตัวเป็นข้อความเพื่อรักษาศูนย์นำหน้า ค่าจ้างและเงินสมทบเป็นตัวเลข ไม่มีตัวอย่าง ชื่อรวม หรือผลรวมท้ายตาราง เงินสมทบในไฟล์เป็นส่วนพนักงาน ไม่รวมสมทบนายจ้าง ข้อมูลบัญชีนายจ้างและงวดเดือนไม่เพิ่มเป็นคอลัมน์ใหม่ ให้ตรวจเทียบและระบุในเว็บ สปส. ตามแบบฟอร์ม

ตรวจข้อมูลขาด เลขประจำตัวไม่ครบ 13 หลัก/ซ้ำ สาขาไม่ครบ และจำนวนเงินผิดรูปแบบก่อนสร้างไฟล์ แก้ค่าจ้างและเงินสมทบได้เอง ปุ่มคำนวณใหม่ทุกแถวใช้ฐานค่าจ้างตามปีและอัตราที่ระบุ เงินสมทบต้องเป็นจำนวนเต็มบาท แบบกำหนดเองไม่แก้ยอดเงินเดือนหรือบัญชีเดิม เปลี่ยนงวดจะขอยืนยันล้างตารางเพื่อลดการใช้ข้อมูลผิดเดือน

แบบนำส่งเป็นข้อมูลระหว่างเปิดหน้าจอ กด **เก็บแบบร่างไว้ทำต่อ** เพื่อดาวน์โหลด JSON และใช้ **เปิดแบบร่างเดิม** นำกลับมาทำต่อ ข้อมูลแบบร่างมีเลขประจำตัวบุคคล ให้เก็บไว้ในอุปกรณ์ที่ดูแลได้ ไม่บันทึกแบบร่างขึ้นฐานข้อมูลโดยอัตโนมัติ

นำ Excel ไปแนบที่เว็บประกันสังคมโดยเลือกประเภท `.xlsx` ไม่ใช่ `.gpg` หรือ `.enc` ฟังก์ชันนี้ยังไม่เข้ารหัส GPG และไม่ยื่นหรือชำระเงินแทนผู้ใช้ ต้องตรวจผลนำเข้าและยืนยันบนเว็บ สปส. เอง ตรวจรูปแบบจาก SampleExcel และเทียบแบบ สปส.1-10 ทั้งสองส่วนที่ผู้ใช้ส่งมา แต่ยังไม่ได้ทดสอบแนบไฟล์จริงในบัญชี สปส.


### PDF ตรวจสอบข้อมูลนำส่ง ส่วนที่ 1–2

ในแบบจัดทำไฟล์นำส่ง แสดงยอดรวมพนักงาน นายจ้าง และยอดรวมต้องนำส่ง หากอัตราสองฝ่ายเท่ากัน ยอดนายจ้างเริ่มต้นเท่ากับเงินสมทบพนักงานที่กรอก หากอัตราต่างกัน คำนวณนายจ้างแยกรายบุคคลจากค่าจ้างที่อยู่ในฐานตามปี ระบุยอดสมทบนายจ้างรวมเองได้เป็นจำนวนเต็มบาท โดยไม่เปลี่ยนเงินสมทบพนักงานใน Excel

เปิด **ข้อมูลเพิ่มเติมสำหรับ PDF และผู้ลงนาม** เพื่อกรอกชื่อสาขา ที่อยู่ รหัสไปรษณีย์ โทรศัพท์ อีเมล ชื่อและตำแหน่งผู้ลงนาม แล้วกด **ดาวน์โหลด PDF ตรวจสอบ ส่วนที่ 1–2** ส่วนที่ 1 สรุปค่าจ้าง เงินสมทบทั้งสองฝ่าย จำนวนผู้ประกันตน และตัวอักษรเงินบาท ส่วนที่ 2 แสดงรายชื่อ ค่าจ้าง และเงินสมทบส่วนพนักงาน พร้อมหัวตารางซ้ำเมื่อขึ้นหน้าใหม่และช่องลงนาม ข้อมูลเพิ่มเติมและยอดนายจ้างที่ระบุเองรวมอยู่ในแบบร่าง JSON และยังเปิดแบบร่างเวอร์ชันเดิมที่ไม่มีช่องเหล่านี้ได้

PDF สร้างจากข้อมูลที่ตรวจสอบในแบบนำส่ง เป็นฉบับตรวจสอบก่อนนำส่งของ BillFlow ไม่ใช่ไฟล์ที่ สปส. ออกให้หลังยืนยัน ไม่มีหมายเลขธุรกรรมหรือสถานะรับยื่น ไม่ใช้ PDF นี้แทนไฟล์ Excel ในขั้นตอนแนบข้อมูล


### เลือกรายชื่อและตรวจสอบก่อนส่งออก

ติ๊ก **นำส่ง** เฉพาะพนักงานที่ต้องการ หรือเลือก/ไม่เลือกทั้งหมด รายชื่อที่ไม่เลือกยังอยู่ในแบบร่าง JSON แต่ไม่รวมในการตรวจข้อมูล ไฟล์ Excel, PDF หรือยอดรวม นำแบบร่างเดิมมาเปิดจะถือว่าทุกคนถูกเลือกหากยังไม่มีค่าการเลือกเดิม เมื่อเปลี่ยนกลุ่มผู้ที่จะนำส่ง ระบบล้างยอดนายจ้างรวมที่ระบุเองเพื่อให้ตรวจใหม่ตามกลุ่มที่เลือก

กด **ตรวจสอบก่อนส่งออก** เพื่อแสดงช่องผิดพลาดเป็นกรอบแดงพร้อมรายละเอียดรายแถวและสถานะข้อมูลครบ ปุ่ม **ไปช่องที่ต้องแก้ไข** เลื่อนไปช่องผิดพลาดแรกในตาราง ตรวจเลขประจำตัวซ้ำทั้งสองแถว เฉพาะคนที่เลือก กรอกชื่อ/คำนำหน้า/นามสกุลและจำนวนเงินให้ครบ หากไม่เลือกใครจะส่งออกไม่ได้ เลขแถวในข้อความตรวจสอบตรงกับลำดับในตาราง แม้มีบางคนไม่ถูกเลือก


### หน้าเว็บประกันสังคมและข้อมูลเข้าใช้งาน

กด **ประกันสังคม** ด้านบนของหน้าเงินเดือน เพื่อเปิดหน้าย่อยประกันสังคม มีตัวเลือกงวดเดือน ปุ่มจัดทำไฟล์นำส่ง สรุปยอด และกล่องเข้าใช้งานเว็บ สปส. ลิงก์เริ่มต้นคือ https://www.sso.go.th/eservices/esv/index.jsp แก้ลิงก์ ชื่อผู้ใช้ และรหัสผ่านได้ ปุ่มเปิดเว็บเปิด HTTPS ในแท็บใหม่ มีปุ่มคัดลอกชื่อผู้ใช้/รหัสผ่าน แสดง/ซ่อนรหัสผ่าน คืนลิงก์เริ่มต้น และล้างข้อมูลเข้าใช้งาน

ชื่อผู้ใช้และรหัสผ่านแยกเก็บแบบเข้ารหัสใน Vault ตามบัญชีผู้ใช้ BillFlow ของแต่ละคน กด **บันทึกข้อมูลเข้าใช้งาน** ใต้ช่องรหัสผ่านเพื่อเก็บลิงก์และข้อมูลเข้าเว็บ เปิดหน้าใหม่ระบบโหลดกลับอัตโนมัติโดยซ่อนรหัสผ่าน ไม่รวมในแบบร่าง JSON, Excel หรือ PDF และไม่ล็อกอินแทน ต้องนำไปวางบนเว็บ สปส. เอง


### การบันทึกข้อมูลเข้าเว็บ สปส.

แก้ไขแล้วกด **บันทึกข้อมูลเข้าใช้งาน** รอข้อความบันทึกสำเร็จและเวลาบันทึกล่าสุด ใช้ **โหลดข้อมูลที่บันทึกแล้ว** เพื่อยกเลิกการแก้ไขและโหลดค่าปัจจุบันจากระบบ การล้างช่องอย่างเดียวยังไม่ลบข้อมูลที่บันทึก ต้องกดบันทึกหลังล้าง หรือใช้ **ลบข้อมูลที่บันทึก** ข้อมูลของแต่ละบัญชีผู้ใช้ไม่แชร์ให้ผู้ใช้อื่นแม้มีสิทธิ์เงินเดือนร่วมกัน

ข้อมูลทั้งลิงก์ ชื่อผู้ใช้ และรหัสผ่านเข้ารหัสใน Supabase Vault ตารางอ้างอิงอยู่ใน billflow_private และไม่เปิดให้อ่านโดยตรง RPC ตรวจตัวตน สิทธิ์เมนู และรุ่นข้อมูลทุกครั้ง ไม่รับรหัสผู้ใช้จากไคลเอนต์ แก้ไขจากหลายอุปกรณ์พร้อมกันจะแจ้งให้โหลดก่อนเขียนทับ เมื่อผู้ใช้ถูกลบ ข้อมูลลับที่เกี่ยวข้องถูกลบด้วย ไม่บันทึกรหัสผ่านในประวัติใช้งานและไม่รวมอยู่ใน payload บัญชี การทดสอบ tests/sso-access.sql ตรวจการสร้าง/โหลด/แก้/ลบ การเข้ารหัส ข้ามบัญชี และสิทธิ์ พร้อม rollback ข้อมูลทดสอบทั้งหมด


### สถานะบันทึกและการปิดหน้าจอ

กล่องเข้าเว็บ สปส. แสดงสถานะ **ยังไม่มีข้อมูลที่บันทึก / ยังไม่ได้บันทึกการแก้ไข / บันทึกข้อมูลแล้ว** พร้อมเวลาบันทึกล่าสุด เมื่อแก้ไขแล้วกลับเป็นค่าเดิม สถานะกลับเป็นบันทึกแล้วโดยไม่เตือนซ้ำ หลังบันทึกสำเร็จรหัสผ่านถูกซ่อน หากยังมีการแก้ไข จะเตือนก่อนกดกลับหน้าเงินเดือนและขอให้เบราว์เซอร์เตือนก่อนรีเฟรชหรือปิดแท็บ การแจ้งเตือนปิดแท็บขึ้นกับเบราว์เซอร์และจะหายหลังบันทึกหรือโหลดข้อมูลเดิม

การเปลี่ยนไปเมนูอื่นของ BillFlow ผ่านแถบเมนูยังไม่ได้อยู่ในตัวป้องกันนี้ ให้กดบันทึกให้สำเร็จก่อนออกจากเมนู
