# เงินเดือนและค่าจ้าง

เมนู **เงินเดือน** ใช้รายชื่อพนักงานเดิมจาก **รายชื่อ / ผู้ติดต่อ → พนักงาน** ในพื้นที่ทำงานของผู้ใช้แต่ละคนตามแบบสิทธิ์เดิมของ BillFlow ไม่ได้รวมบัญชีของพนักงานเข้ากับบัญชีเจ้าของร้าน

1. สร้างร่าง เลือกพนักงาน รอบวันที่ วันครบกำหนด ค่าจ้างรายเดือน / รายวัน / รายชั่วโมง และจำนวนหน่วย
2. เพิ่มรายได้ เช่น OT เบี้ยเลี้ยง โบนัส คอมมิชชัน และรายการหักแยกประเภท ภาษี ประกันสังคม กองทุน เงินเบิกล่วงหน้า ขาดงาน และอื่น ๆ
3. ตรวจยอดแล้วอนุมัติ กำหนดวันลงบัญชี ยอดที่อนุมัติแล้วล็อกไว้ การแก้ไขให้คืนรายการจ่ายทั้งหมดและยกเลิกรอบพร้อมเหตุผล แล้วจัดทำใหม่
4. จ่ายได้หลายครั้ง แต่ละครั้งระบุยอด วันที่ บัญชี วิธีจ่าย อ้างอิง หมายเหตุ และแนบหลักฐาน ยอดจ่ายห้ามเกินยอดสุทธิคงเหลือ
5. ดูประวัติแบ่งจ่าย พิมพ์สลิป / บันทึก PDF ผ่านหน้าต่างพิมพ์ และส่งออกสรุป CSV ตามเดือนสิ้นสุดรอบ

จำนวนเงินเก็บเป็นสตางค์ ค่าจ้างรายวันและรายชั่วโมงคำนวณจากหน่วย × อัตราแล้วปัดครั้งเดียว รายการ OT รับเป็นยอดรวมที่ตรวจสอบแล้ว ภาษีและประกันสังคมเป็นยอดกรอกเอง ไม่มีการยื่น ภ.ง.ด.1 / สปส.1-10 หรือคำนวณภาษีรายปีอัตโนมัติ เงินเบิกล่วงหน้าที่หักต้องมีลูกหนี้พนักงานบันทึกไว้ก่อน

## บัญชี

อนุมัติแล้วตั้งรายได้รวมเข้าค่าใช้จ่าย 520000 หักขาดงานเครดิตลดค่าใช้จ่าย ภาษีค้างจ่าย 213000 ประกันสังคม 216000 กองทุน 217000 รายการหักอื่นรอนำส่ง 218000 และเงินเดือนสุทธิค้างจ่าย 219000 เงินเบิกล่วงหน้าตัดลูกหนี้อื่น 111000 เงินสมทบนายจ้างตั้งค่าใช้จ่าย 522000 และหนี้ประกันสังคม 216000

จ่ายเงินจริงสร้างรายการเงินออกหนึ่งครั้งและเดบิต 219000 โดยไม่ตั้งค่าใช้จ่ายเงินเดือนซ้ำ ยกเลิกการจ่ายต้องยืนยันว่าได้รับเงินคืนจริง ระบบเพิ่มเงินรับกลับเข้าบัญชีเดิมและเก็บรายการเดิมทั้งหมด ยกเลิกเงินเดือนกลับรายการตั้งค้างจ่าย ณ วันที่ยกเลิก รายการอนุมัติและกลับรายการคำนวณใน postings จากหลักฐานเงินเดือน ส่วนกระแสเงินสดอ่านรายการจ่าย / รับเงินจริง

## สิทธิ์และประวัติ

เจ้าของเข้าถึงได้เสมอ สามารถกำหนดให้ดู / แก้ไขเมนูเงินเดือนแยกกัน ผู้จัดการที่เลือกใช้สิทธิ์มาตรฐานจะได้เมนูนี้ พนักงานทั่วไปและแอดมินร้านไม่ได้สิทธิ์นี้โดยอัตโนมัติ ผู้มีสิทธิ์เงินเดือนต้องมีสิทธิ์แก้ไขรายการรับ–จ่ายร่วมด้วยจึงจ่าย / คืนเงินได้ สิทธิ์การอ่านข้อมูลการเงินยังใช้การฉายข้อมูลทางการเงินชุดเดียวกับเมนูสมุดบัญชีและรายงานเดิม

ฐานข้อมูลตรวจยอดและความเชื่อมโยงการจ่าย ล็อกยอดอนุมัติ รายการจ่ายเดิม และป้องกันเบราว์เซอร์รุ่นเก่าลบข้อมูลเงินเดือนโดยไม่ตั้งใจ ทุกการเปลี่ยนเงินเดือนบันทึกประวัติฝั่งเซิร์ฟเวอร์พร้อมข้อมูลผู้ใช้งานและอุปกรณ์เดิม การล้างข้อมูลทั้งระบบยังอยู่ภายใต้ตัวป้องกันสมุดบัญชีเดิม

## ตรวจสอบ

`npm test` รวมกรณีอนุมัติ เงินเดือนค้างจ่าย แบ่งจ่ายสองครั้ง จ่ายเกิน คืนรายการ กลับบัญชี รายวัน รายชั่วโมง และการล็อกประวัติ

`tests/payroll.sql` ตรวจฐานข้อมูลผ่านบทบาท authenticated พร้อมย้อนกลับธุรกรรมท้ายชุด จึงไม่คงข้อมูลทดสอบ


## แบบฟอร์มและเอกสารจาก LINE

สลิปมีเลขเอกสาร สำเนาร้าน / พนักงาน รหัสพนักงาน แผนก ช่วงวันที่ วันหยุด วันทำการ วันลา ขาดงาน วันทำงานจริง อัตราจ้าง และเงินเดือนเต็มเดือนอ้างอิง รายได้และรายการหักอยู่สองฝั่งตามตัวอย่าง พร้อมจำนวน × อัตรา ยอดรวม สุทธิเป็นตัวเลขและตัวอักษร วันที่แจ้ง / จ่ายจริง วิธีจ่าย หลักประกันอ้างอิง และผู้ลงนาม สามารถกำหนดข้อความท้ายเอกสารได้ ข้อมูลวันทำงานและหลักประกันอ้างอิงไม่หักเงินซ้ำอัตโนมัติ

รูปเงินเดือนจากกลุ่ม LINE เดิมจะถูกแยกเป็นเอกสารชนิด payroll ระบบอ่านค่าจ้าง รายได้ หัก และข้อมูลวันทำงานลงแบบตรวจเอกสารเงินเดือน จับคู่พนักงานด้วยรหัส / ชื่อที่ตรงเพียงคนเดียวเท่านั้น หากรหัสและชื่อขัดกันต้องเลือกเอง ไม่สร้างพนักงานใหม่อัตโนมัติ การแปลงหน่วยบาทเป็นสตางค์เกิดเพียงครั้งเดียว รายการหักจำนวน 3 × อัตรา 19 บาท = 57 บาทจะเก็บจำนวน อัตรา และยอดแยกกัน

ก่อนยืนยันต้องเทียบรายได้รวม หักรวม และสุทธิกับยอดจากรูป หากไม่ตรงต้องตรวจแก้ ระบบยืนยันเข้าร่างเงินเดือนพร้อมแนบรูปเดิมเท่านั้น ไม่สร้างรายการจ่ายหรือประวัติชำระจากการอ่านภาพแม้ภาพติ๊กว่าโอนเงินแล้ว ต้องอนุมัติและบันทึกแบ่งจ่ายตามหลักฐานแยกต่างหาก รองรับข้อมูลเก่าไม่มีรายละเอียดแบบฟอร์ม เอกสารที่อนุมัติแล้วยังคงล็อกข้อมูลเดิม

ทดสอบตัวอย่างค่าแรง 300 × 12 = 3,600 บาท หักประกันสังคม 350 และรายการ 3 × 19 = 57 รวมรายการหัก 407 สุทธิ 3,193 บาท โดยไม่ใช้ข้อมูลพนักงานจริง ชุด SQL ตรวจยืนยันนำเข้าจาก LINE ป้องกันสูตรผิด วันเกินรอบ และนำเข้าซ้ำ แล้ว rollback ข้อมูลทดสอบทั้งหมด


### สถานะการเปิดใช้ตัวอ่านเงินเดือน

ผู้ใช้อนุญาตชัดเจนให้ส่งภาพเงินเดือนจากกลุ่ม LINE ที่ผูกไว้ไปยัง Google Gemini เพื่ออ่านและกรอกแบบฟอร์ม เมื่อวันที่ 29 ตุลาคม 2569 เผยแพร่ billflow-line เวอร์ชัน 13 สำเร็จและตรวจสอบว่า source ตัวอ่านตรงกับที่ทดสอบ พร้อมคงการยืนยันตัวตนและ CORS เดิม ไม่ส่งข้อความหรือรูปทดสอบเข้ากลุ่ม LINE ในการเปิดใช้ครั้งนี้ ยังไม่ได้ทดสอบส่งภาพจริงผ่าน LINE หลัง deploy การอ่านต้องใช้ Gemini API key และโควตาที่ตั้งค่าไว้ ผลเข้าร่างรอตรวจ ไม่สร้างรายการจ่ายจากภาพอัตโนมัติ


## รับ PDF จาก LINE

ส่งไฟล์ PDF ผ่านกลุ่มเดิม รองรับไม่เกิน 5 MB โดยตรวจนามสกุลและส่วนหัวไฟล์ PDF ก่อนเก็บต้นฉบับและส่งให้ Gemini ด้วย MIME application/pdf ใช้การตรวจลายเซ็น LINE การจำกัดกลุ่ม และโควตาเดิม ป้องกันรูปหรือ PDF ซ้ำด้วยแฮชเนื้อหาเดิม หน้าเปิดตรวจแสดง PDF และมีลิงก์เปิดต้นฉบับในแท็บใหม่

PDF หลายหน้าที่เป็นเอกสารเดียวกันอ่านร่วมกันได้ แต่หากตัวอ่านตรวจพบหลายพนักงาน / หลายเอกสารในไฟล์เดียวจะไม่ยอมรวมยอด ต้องแยกไฟล์ก่อนนำเข้า ผลเงินเดือนยังเป็นร่าง ไม่ตัดบัญชีอัตโนมัติ ชื่อไฟล์แนบในระบบคงนามสกุล .pdf และ MIME เดิม ไฟล์ติดรหัสผ่านหรือเสียหายต้องแก้ที่ต้นฉบับ

ทดสอบรับ webhook PDF การตรวจส่วนหัว/ขนาด การส่งไบต์ PDF ให้ตัวอ่านจำลอง การแปลงยอดเงินเข้าร่าง และการไม่รวมหลายพนักงาน ยังไม่ได้ส่ง PDF จริงผ่านกลุ่ม LINE ในการอัปเดตครั้งนี้
