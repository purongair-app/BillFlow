# สิทธิ์ย่อยตามบัญชีเงิน

เจ้าของเปิด **สิทธิ์ผู้ใช้งาน → แก้สิทธิ์ → สิทธิ์ย่อย · บัญชีที่อนุญาตให้เห็น** แล้วเลือกขอบเขตบัญชีก่อนบันทึก

- **ทุกบัญชี**: เห็นบัญชีปัจจุบันและบัญชีที่เพิ่มภายหลัง ตามเมนูที่ได้รับสิทธิ์
- **เฉพาะบัญชีที่เลือก**: เลือกเงินสดหรือบัญชีธนาคารได้หลายบัญชี บัญชีใหม่ไม่ถูกเพิ่มให้อัตโนมัติ
- ไม่เลือกบัญชีใด: ไม่ได้รับข้อมูลบัญชีและรายการการเงิน

สิทธิ์แก้ไขยังแยกจากสิทธิ์ดูตามเมนู เจ้าของเห็นทุกบัญชีเสมอ การเปลี่ยนขอบเขตจะถูกตรวจอีกครั้งทุก 30 วินาทีหรือเมื่อกลับเข้าแท็บ และทุกครั้งที่บันทึกบนเซิร์ฟเวอร์

รายการโอนที่มีปลายทางหรือบัญชีต้นทางอยู่นอกสิทธิ์จะเก็บวันที่และยอดโอนสำหรับคำนวณยอดของบัญชีที่มองเห็น ซ่อนรายละเอียดอีกบัญชีและเอกสารแนบ และดูได้อย่างเดียว รายการเงินเดือนหรือชำระหนี้ที่แสดงในบัญชีที่อนุญาตจะดูได้อย่างเดียวเช่นกัน

โหมดเฉพาะบัญชีปิดเมนูหนี้ เงินเดือน รายจ่ายประจำ และเอกสาร LINE เพราะข้อมูลเหล่านี้มีส่วนที่ยังไม่ผูกบัญชีเงิน ยอดรวม/สมุดบัญชี/รายงานในโหมดนี้เป็นข้อมูลเฉพาะขอบเขตบัญชี ไม่ใช่งบการเงินทั้งกิจการ สมุดบัญชีในขอบเขตนี้ดูได้อย่างเดียว ไม่ส่งรายการปรับปรุงรวมของร้านให้ผู้ใช้

## การติดตั้ง

1. ตรวจและอนุมัติ `supabase/account-permissions.sql` ก่อนใช้กับฐานข้อมูลจริง แล้วติดตั้ง SQL ผ่าน migration ของโครงการ Supabase เดิม
2. SQL เพิ่ม `account_ids` ในสมาชิกและปรับ RPC กับ Storage RLS ไม่แก้ไขรายการการเงินหรือเลือกสิทธิ์แทนเจ้าของ สมาชิกเดิมคงโหมดทุกบัญชี (`NULL`) ไว้
3. เผยแพร่ frontend หลังติดตั้ง SQL สำเร็จ เพราะหน้าสิทธิ์ใช้ RPC `billflow_manage_members_v3`
4. ให้เจ้าของเลือกบัญชีตามผู้ใช้จริง ตรวจด้วยบัญชีทดสอบว่าเห็นเฉพาะบัญชีที่เลือก ดูเอกสารแนบที่อนุญาตได้ และบันทึกแล้วบัญชีที่ซ่อนไม่เปลี่ยน

`npm test` รวมการทดสอบฐานข้อมูล Postgres แยกจาก production ด้วย PGlite: กรองข้อมูล, สิทธิ์เจ้าของ, ป้องกันปลอม ID/ย้ายบัญชี, เก็บแถวที่ซ่อน, โอนแบบปิดรายละเอียด, revision conflict และ restrictive Storage policy ร่วมกับ policy เดิม ส่วนตัวตรวจ payload และระบบ Auth ในชุดจำลองใช้ fixture; ต้องทดสอบผ่านผู้ใช้จริงอีกครั้งหลังติดตั้งที่ได้รับอนุมัติ
