# Recurring expense reminders

The former Budgets menu is now รายจ่ายประจำ. Existing budgets remain in backups; no transaction or balance is changed by creating a reminder. The internal `budgets` permission key is retained, with separate viewing and editing rights, and each user still has their own ledger. Only the existing owner's paired LINE group currently has a delivery connection.

Add a title, monthly/yearly frequency, first due date, optional estimated amount (integer satang; zero means awaiting the real bill), and any combination of 3/7/15/30 lead days. Monthly dates retain the original day; short months use their last day. Annual February 29 uses February 28 outside leap years. The first date is the earliest permitted occurrence. Marking the next occurrence paid stores `paidThrough`, stopping reminders for that occurrence and earlier ones; this does not post payment to the ledger. Users must record actual payments separately.

`private.billflow_line_tick()` runs every minute, calling the private producer before checking the existing queue. From 09:00 Asia/Bangkok each day it matches today plus each selected lead against the recurrence. A unique `(owner, revision=0, entry_id=recurring:<schedule>:<due>:<lead>, action=reminder)` prevents duplicate reminders. Delivery uses the existing retry queue and LINE retry key. The main LINE enabled switch must be on and the group must remain paired. Editing, pausing, deleting or marking paid invalidates queued notices, with an additional service-only check just before delivery. No backfill of reminders for earlier calendar days is performed.

Database changes: `supabase/recurring-expenses.sql`. The existing ledger/storage isolation is unchanged. Recurring data is projected and merged according to the existing menu permission. A database trigger validates every saved recurring setting. Scheduler and validity helpers are revoked from public/anonymous/authenticated roles; only the validity RPC is granted to service_role.

Validation: 36 unit tests and production build pass. `tests/recurring-expenses.sql` verifies the database producer, 09:00 cutoff, monthly/yearly lead days, deduplication, payment cancellation, date clamping, server validation, and own-ledger permission checks, inside a rolled-back transaction. Preview infrastructure was unavailable, so browser visual QA was not performed. No sample recurring bills or test LINE pushes were persisted.

## Managed expense names and repeat checkbox

The expense name picker now has a จัดการชื่อรายจ่าย button. A per-ledger catalog supports adding, renaming and deleting names with trimmed, case-insensitive uniqueness. Six initial names appear until the user saves their catalog. Renaming a name updates matching configured reminders; deleting a picker name preserves configured reminders. Empty catalogs are valid. The same budgets view/edit permission covers this catalog.

Each reminder has an explicit ทำซ้ำรายการเดิมทุกเดือน checkbox (ทุกปี when yearly). `repeat` defaults to true when absent for compatibility. Unchecked reminders match only `startDate`; their paid or past status is shown without scheduling future cycles. LINE labels them ครั้งเดียว. No receipt or financial payment is generated by repeating a reminder.

Migration: `supabase/recurring-names-repeat.sql`. Validation now includes 38 unit tests, a production build, and rolled-back SQL tests for saved names, duplicate rejection, own-ledger permissions, and single-occurrence behavior. A live test reminder was requested by the user for the paired admin group; its temporary schedule is removed after verifying the delivery result, while the outbox delivery record is retained.
